Leon Lin's Cook workflow, step by step, with one running example

How Leon Lin prompts an agent to build demos that hold up next to their references, and how his /cook skill runs the same steps as a loop. Written 2026-11-12.

1. The main idea

Leon says the prompt text is not the most important part. In his words, "the references carry most of the quality in your prompt. The text stuff 'barely' matters." Article

The skill states the method in one line: "Give your agent a target, a bar and time, then let it cook." Skill So the agent gets four things:

  1. A target. Reference images or videos. They show the result that you want.
  2. A bar. A number. It tells the agent how close to the target the work must get.
  3. Rules. What the agent must not use, for example downloaded assets or typical "AI look" patterns.
  4. Time. A minimum time for a demo, or a maximum time for a small job.

Then the agent works in rounds. In each round it builds, renders stills, compares them with the references, gets scores from judges that did not build the work, and fixes the weakest part. It stops only when the work reaches the bar. Leon calls this the Cook Loop. Article Skill

3. The loop on one page

The setup steps (orange row) run one time. The round (teal ring) repeats. The skill expects runs of "10 to 40 hours or more" and rounds of 30 to 90 minutes. Skill

4. Phase A: set up the run

Step 1. Write a short prompt and attach strong references

What Leon does. He starts most big demos with 9 to 12 reference images and a short prompt. Article The skill lists the real counts: Athenaion (the Greek world) used 9, Shanshui and the golden temple used 10, the alpine lake used 10 to 12. Skill

For 3D, Leon makes the references himself with GPT Image Gen. Then he tells Opus 5.5 to build or clone them in code. Article For UI he uses screens of real products, mostly from Mobbin, and posts he sees on X. For motion he uses reference videos. Article

A reference does not always need a 1:1 copy. For his night city stills, Leon asked for "the same quality and mood, but in its own art style". Article In that mode the agent matches light, color and detail density, but not the layout. Skill

Example

You make 10 images of the harbor town with GPT Image. You also find 2 drone-style clips for the camera feel. You attach all 12 files and send this prompt. It is the "short version" from templates/brief.md, filled in: Skill

/cook
Recreate the 10 attached references in three.js, code only, no assets. Match them 99.9%.
The 2 clips are for camera motion only.
At least 8h. Stills after every round, no final render before I approve.
Questions now, then go cook.

The prompt has 5 lines. It does not describe the look in words. The images carry the look.

Why

An image shows light, color, materials, composition and mood together. Words cannot carry those as well. Leon: "a picture is worth a thousand words. The images will show how the light, colors, and materials are, which is hard to describe in words." Article

A long description also has a second problem: the model can read it as something different from the picture in your head. A reference removes that guess. Video

The skill tells the agent not to push you to describe the look in words: "A short prompt with strong references beats a long description." Skill

Leon's full Greek world prompt (Opus 5.5 xhigh, 9 reference images)

This is Leon's real prompt from the article. Article It is longer than the short version, but it still does not describe the look. Every line sets a bar, a rule or a process.

Build me a massive, ultra-detailed 3D world in three.js based on the 9 reference images I attached.
Rules:

- Match the references as closely as possible (aim for 99.9%): composition, scale, materials and
  especially the colors. Cinematic and realistic, not oversaturated, but also not grey or washed out.
- Detail everywhere. Nothing should look copy-pasted or simple. Every building, tree, rock and
  waterfall gets care, and the world has to read as ultra detailed even from far away.

  rendering instead.

Process:

  cinematic background music from the web (credit the artist).

Step 2. Intake: ask every question one time, then never again

What the skill does. The agent first reads everything you gave it. Then it sends one message with only the questions that are still open. Each question has a number and a default, so you can answer by number or reply "defaults". The message ends with: "If you have anything else, tell me now. After this I work without asking until it is done." Skill

The skill has 10 questions: what and which stack, references (close copy or own style), the bar, time (minimum or maximum), hard rules, the deliverable, hardware, usage limits, permissions (download, push, publish), and "anything else". Skill

Two special cases: if you say you are leaving ("I'm going to bed, decide everything"), the agent sends no questions and uses the defaults. If you have no idea yet ("surprise me"), the agent researches ideas, offers 3 to 5, and works on the idea with you before the run starts. Skill

Example

Your prompt already answers questions 1 (what and stack), 3 (the bar), 4 (time) and part of 5 (no assets). So the agent asks only the rest:

Agent, 21:05
2. Recreate the 10 images closely, or match their quality in an own style? Default: recreate closely.
5. Sound and extra bans? Default: code-made sound only if it truly holds up, otherwise licensed free audio with credits. The default slop ban list.
6. Deliverable? Default: approved stills, then about 1 minute of video, 1080p 30fps, no text on screen, licensed music.
7. Hardware? Default: a weak integrated GPU. Realtime kept cheap, quality from offline rendering.
8. Usage limits? Default: a 5h window, about 20% per hour, about 99% per window, never 100%.
9. May I download audio, push to a public repo or publish? Default: download free licensed audio only and credit it. Prepare the repo locally, do not push.
10. Anything else before you leave?
If you have anything else, tell me now. After this I work without asking until it is done.
You, 21:12
2: closely. 7: Radeon 780M laptop. 9: no download, I add the music myself. Rest defaults.

The agent then writes cook/BRIEF.md, copies the template to cook/ROUNDS.md, and logs the start time:

# Brief: harbor-dusk

Target: a harbor town at dusk, recreated from 10 references. Stack: three.js.
References: cook/refs/R01 to R10, recreate closely. V01, V02 for camera motion only.
Bar: composition 99.9, light 99.9, color 99.9, materials 99.9, detail near and far 99.9, motion 9/10.
Calibration offset: none yet.
Rules: zero external assets. No downloaded audio (user adds music). Default ban list.
Time: floor 8h. Started: 2026-11-10 21:15.
Usage: 5h window, about 20% per hour, never 100%.
Hardware: integrated Radeon 780M. Realtime cheap, final quality offline.
Deliverable: approved stills, then a 1 minute video at 1080p 30fps, no text on screen.
Permissions: download no, push no, publish no.
User's words: "Recreate the 10 attached references in three.js, code only, no assets. Match them 99.9%."

From now on, the agent never asks. When it must decide something, it decides and writes one line under "Decisions" in ROUNDS.md, for example: "21:20 harbor water level set from R03, because R03 shows the most of the quay."

Why

The run goes on through the night. Leon: "you DON'T want the agent asking you questions in the middle of the night." Article A question at 03:00 stops all work until you wake up. The defaults let you answer in about 2 minutes. Skill

The brief stays short and uses your own words because every line steers the run. The skill gives a real case: one stray line, "There are no photographs", kept the agents from using photos at all. Skill For the same reason, the agent cleans up a dictated or messy prompt but does not rewrite it or add requirements. Skill

Step 3. Target: turn every reference into a shot

What the skill does. The references are "the minimum bar, not inspiration". The agent studies every reference at full size before it writes code. Skill It copies them into cook/refs/ with stable names (R01, R02 for images; V01, V02 for videos) and keeps the original filenames in the brief. Then it writes cook/SHOTS.md: one shot per reference image, with the camera, the framing, the time of day, what to take from the image, and what to watch for. Skill

Example

cook/SHOTS.md, first 3 of 10 rows:

ShotRefShowsCameraTake from itWatch for
S01R01The harbor from the sea, town on the slopeLow, 35mm, looking east, sun behind the cameraWarm light on the walls, blue-violet shadows, water reflectionsEach house must differ; no copy-paste roofs
S02R02Half-wide view over the roofs to the far hillsHigh, 50mm, looking northHaze layers, roof color varietyFar hills need trees and terraces, not a flat color
S03R03The quay at eye level, boats at the wall1.6 m high, 28mmWet stone, foam at the wall, rope and paint detailWater must not look like plastic

One reference can lead on one thing and be ignored on another. Here R02 leads on haze, and R03 leads on materials.

Motion references: frame by frame

Leon tells the model three things about reference videos: analyze every video frame by frame; write down every small effect, transition and timing in a list; take inspiration from all of them, but never copy one element 1:1. Article

The skill adds the commands and the numbers. It extracts frames at 10 fps, and every frame near cuts. It makes contact sheets to see the rhythm. It writes one line per effect into cook/MOTION.md. Then it picks a core of about 20 strong effects plus 50 to 80 small ones, from many references. It never names the source clips in public files. Skill

Example 
ffmpeg -i cook/refs/V01.mp4 -vf fps=10 cook/refs/V01/f_%04d.png
ffmpeg -i cook/refs/V01.mp4 -vf "fps=2,scale=480:-1,tile=6x5" cook/refs/V01_sheet_%02d.png

Two lines from cook/MOTION.md:

V01 00:03.2-00:07.8 | camera rises past a stone wall, view opens | ease-in-out, ~4.6 s, upward | the reveal hides the town, then shows it all
V02 00:11.0-00:12.4 | camera drifts sideways while it moves forward | slight lateral drift | it feels hand-flown, not on a rail
Why

The agent needs a fixed goal before it builds. Then its job is only to match that goal as closely as it can. Video A shot list with fixed cameras also makes every round comparable: the same frame, from the same position, every time. Skill

For motion, the skill says "All the text moves like this" is about 1% of what a reference video holds. A frame-by-frame list captures the other small things: timing, easing, direction. Taking from many sources keeps the result original. Skill

Step 4. Bar: set a number for each dimension

What Leon does. He writes a number into the prompt: "Match the references as closely as possible (aim for 99.9%)" for the Greek world, and "98% close to the reference images is the minimum bar" for the pianist film. For video he uses ratings: "the reference videos are about an 8.5/10, yours needs to reach at least 9/10". Article

The skill splits the bar into dimensions and scores each one separately. Skill

DimensionWhat the critics checkTypical failure
CompositionFraming, scale, horizon, focal point, layoutSubject too small, empty foreground, wrong lens
LightDirection, softness, shadows, atmosphere, time of dayFlat light, no haze, hard shadows
ColorHue, saturation and brightness per regionGrey and washed out, or oversaturated
MaterialsHow water, stone, foliage, metal and skin take lightPlastic look, flat water
Detail densityNear and far, variety, no visible repetitionBare trees in the distance, copy-pasted rocks
MotionTiming, easing, transitions, camera movesLinear moves, cheap transitions, jitter

Stills get 0 to 100 (similarity to the reference). Video and motion get 1 to 10. Skill

Calibration: your estimate corrects the scores

Leon: "If it says it's at 90% and I think it's at 60-70%, I tell it exactly that, so it knows how high my expectations are." Article The skill turns this into arithmetic. The gap between your estimate and the reported score becomes an offset. In Leon's example the offset is about −25. The agent subtracts it from every later critic score until you give a new estimate. Skill

The skill also keeps two kinds of numbers apart. A measured number came from a command in this round. An eyeballed number came from a person or a model. A similarity percentage is eyeballed unless a command computed it. Skill

Example

The brief says 99.9 for each still dimension and 9/10 for motion. No offset yet. Step 8 shows the offset being set at 23:40.

Why

"Make it look good" gives the agent no point where the work is done. A number does. Article

Leon says 99.9% is probably not realistic, and that is the purpose: "the number tells the model that the job is not done when it first works." Article The video rating works the same way. 9/10 is above the 8.5 of the references, and Leon calls it "not an achievable goal". But AI rates its own work too high, so a target above the references pushes it further. Article

One number per dimension, not one total, means "the weakest dimension cannot hide behind the others." Skill The calibration offset is necessary because models rate their own work too high, and critic agents "share some of that bias". Skill

Step 5. Rules: code only, honest sound, ban the slop

Zero external assets

Leon's rule: "Use zero external assets. Every mesh, texture, shader and effect has to be generated in code." Article He gives two reasons: it is the impressive part ("people often don't believe it"), and "it forces the model to actually build things instead of downloading a tree". So the demo shows what the model can really do. Article If anything external is used, it goes in the credits. It is never hidden. Skill

Exceptions: code-made music sometimes holds up (the Chinese landscapes, the alpine lake), but code-made sound effects often sound cheap, especially in launch videos. Then Leon uses professional free sound libraries and credits them. For launch videos, real logos and real photos look better than SVG people. Article

The slop ban list

"Every prompt has a list of things the model is not allowed to use." Article The combined list from the article and the skill:

  • eyebrow labels; monospace uppercase text; random serif fonts
  • beige; purple gradients, and purple as a default accent Skill
  • 01 / 02 / 03 counters; glowing orbs; shockwave rings popping out of things
  • decorative particles; long thin decorative lines Skill
  • em dashes in any text
  • in motion: generic moves, for example an icon that floats up for no reason Skill
  • in sound: rising-pitch whips and cheap synth bells Skill

Films and world showcases usually get no text on screen at all. Skill

Color, detail and a weak GPU

Color must match the references: not grey, not washed out, not oversaturated. The skill calls color "one of the most important things and the most common failure". If everything is grey, the agent checks the pipeline first (output color space, tone mapping, exposure, fog color) before it repaints materials. Skill

Detail: every building, tree and rock varies in shape, color and scale. The world must look detailed from far away, so the agent never cuts the draw distance in final renders. Skill

A weak GPU is not a reason for lower quality. The realtime preview stays cheap. Stills and the final video render offline, frame by frame, at full quality. The method is sub-frame accumulation: render several sub-frames for each output frame and average them. Each sub-frame moves one thing a small amount: the time inside the shutter (gives motion blur), the light position (soft shadows), the lens position (depth of field), or the sub-pixel offset (anti-aliasing). Animation is driven by the frame number, not the wall clock, so every render is the same. Skill

Example

For the harbor, the rules mean:

  • Houses, boats, stone, water and sky are all made in code. No downloaded textures or HDRI sky.
  • No text on screen. No decorative particles: the agent does not add floating sparks "for atmosphere" that the references do not show.
  • The lanterns on the quay are allowed, because R03 shows them. A glowing orb with no source in the references is not allowed.
  • The realtime preview runs at a low resolution. Each still renders offline with 16 sub-frames.
  • You add the music, because the brief says "download no".
Why

The banned patterns are the details that show at once that AI made a page. Video When you name them, the agent stops using them. The color rule is there because "too grey" is Leon's most common feedback on 3D builds. Article The offline path is there because Leon renders on an integrated Radeon 780M. Article

Step 6. Time: a minimum or a maximum, and pace the usage

What Leon does. "The same model gives you something completely different in 20min vs 20h." So he always gives a time budget. For demos it is a minimum: "This task should take at least 8h. If you are done after 2h, something is wrong." For big builds he says it might take days. Small jobs get a hard cap, for example "max 1.5h", because "otherwise it will work for wayy too long". Article

The Greek world took about 45 h in total, 55 subagents (up to 12 in parallel), about 45k lines of JavaScript, about 11M output tokens, and about $1.8k to $2.3k at Opus 5.5 API prices. It ran on a Max plan. Article

Usage pacing. Leon tells the agent to "use about 99% of the 5h limit in those 5h, but never hit 100%". Article The skill turns that into about 20% of the window per hour. At each round boundary the agent compares its usage with that pace. Ahead of pace: fewer parallel subagents, more planning and critique. Behind pace: more parallel subagents. Near the end of a window, it finishes the current step and writes the ledger, so a hard stop never lands in the middle of a change. Skill

Depth over breadth. The agent makes one shot exceptional before it expands. "A small exceptional level beats a large mediocre one." Skill

Example

Start 21:15, floor 8h. So the earliest stop is 05:15. The first usage window runs 21:15 to 02:15.

At 23:05, 1 h 50 min into the window, the pace allows about 37% (1.83 h × 20%). The agent reads 47%. It is ahead of pace, so it reduces the parallel builders in round 2 from 6 to 3.

Why

Without a minimum, the agent "stops as soon as the page works, which is before the page looks as good as it can". Video Without pacing, Leon says, "it burns everything in 2h and waits for 3h". Article

Some models stop early and write a summary. Leon names Argon and, earlier, Opus 5. His /unlazy skill fixes that: split the task into subtasks, split those again a few layers deep, and give every leaf as much effort as the whole task would normally get. He says this is "not really necessary for newer models like Opus 5.5". Article Cook lists /unlazy as an optional companion. Skill

Step 7. Build the harness before round 1

What the skill does. Before round 1, the agent builds the tools that every round reuses: Skill

  1. A fixed camera preset for each shot: position, target, field of view, time of day.
  2. A still renderer that writes cook/stills/rNN/S01.png and so on, with the offline quality path, at the aspect ratio of the reference.
  3. A side-by-side script: reference left, render right. The skill includes one, scripts/side-by-side.mjs (needs Node 18+ and ffmpeg).
  4. A color check (Python, Pillow, NumPy). It compares mean saturation and brightness on a 4×4 grid, reference against render.
  5. For video: a contact-sheet renderer and a short-clip renderer.
Example

The camera presets in the harbor project (the file name is my choice; the skill does not set one):

// shots.js — one fixed camera per reference
export const SHOTS = {
  S01: { pos: [-42, 6.5, 88],  target: [0, 4, 0],   fov: 38, hour: 19.4, aspect: 16/9 },
  S02: { pos: [-10, 48, -20],  target: [0, 12, -260], fov: 27, hour: 19.4, aspect: 16/9 },
  S03: { pos: [6, 1.6, 14],    target: [0, 1.2, 0], fov: 54, hour: 19.5, aspect: 16/9 },
  // ... S04 to S10
};

The side-by-side command for round 1:

node <skill>/scripts/side-by-side.mjs --out cook/compare/r01/all.jpg \
  cook/refs/R01.png cook/stills/r01/S01.png \
  cook/refs/R02.png cook/stills/r01/S02.png \
  cook/refs/R03.png cook/stills/r01/S03.png

The script fits each image into the same 16:9 box (default 540 px high) with black bars, so it never stretches an image. Each pair becomes one row. Skill

Why

The harness makes each round cheap to check. Fixed cameras give the identical framing every round, so a score change comes from the work and not from a moved camera. The color check catches "too grey" with a number "before the user has to say it". Skill

5. Phase B: the rounds (step 8)

Each round has 9 sub-steps. Skill Round 1 below shows all 9 in detail. Rounds 2 to 10 show only what is new in them.

Round 1 (21:55 to 23:05): all 9 sub-steps

8.1 Focus

The skill picks the focus in this order: (1) open items in your feedback inbox; (2) any shot with a dimension far below the bar; (3) the dimension with the largest total gap across all shots; (4) far distance and detail density, "which are easy to forget". Skill

Example

Nothing exists yet, so round 1 builds the base world: terrain, sea, sky, and a rough version of the town. Every shot can then render, so every later round has something to compare.

8.2 Fix it in depth, with parallel subagents

Independent parts go to parallel subagents. Each builder gets the brief, the shots it owns, the files it may change, and its done condition. The main agent stays the owner: it integrates the parts, decides, and keeps the ledger. Skill

Example

6 builders run in parallel: terrain, sea surface, sky and fog, houses, boats, and the quay wall. The houses builder owns town/*.js and S01 and S02. Its done condition: "every house differs in height, roof pitch and wall color; S01 renders with no error."

8.3 Render stills

The agent renders each shot from its camera preset, with the same framing and aspect as the reference. For motion it renders contact sheets and short clips. Skill

8.4 Make side-by-side images

Reference left, render right, one row per shot. These images are the only input the critics get.

8.5 Measure what a command can measure

Color per region, frame time, seconds per rendered frame. Skill

Example 
python color_check.py cook/refs/R01.png cook/stills/r01/S01.png
saturation: mean delta -0.118, worst cell -0.204
brightness: mean delta -0.041, worst cell -0.097

A negative saturation delta means the render is greyer than the reference. Skill −0.118 is a large gap: S01 is clearly too grey.

8.6 Score with fresh-context critics

A critic is a new subagent with no history, no code, no brief and not the builder's own score. It does not learn who built the work, how long it took, or what the builder thinks of it. It gets only the side-by-side images and the rubric. Skill

At least 2 critics per round, 3 or more for big builds. A different model as one of them helps. The agent takes the median per dimension. If two critics differ by more than 10 points (or 1.0 on a 10-point scale), it adds another critic. The builder's own score is logged but never decides anything. Skill

Leon: "The agent that built something is the worst judge of its own work." His prompt line: "Rate it with subagents that have no context. Don't stop before it reaches 9.2/10." He also uses other models, for example GPT 6.1 Sol to judge Opus 5.5's work. Article

Example

The critic prompt, from references/loop-and-critics.md, with the bar filled in:

You are a strict art director seeing this work for the first time.
Each image shows a reference on the left and a render on the right.
For each image, score how close the right side is to the left side, 0 to 100, on:
composition, light, color, materials, detail density (near and far).
100 means a viewer could not tell which one is the reference. The bar is [99].
Then list the 3 biggest gaps per image: where (region), what is wrong, what to change.
End with the single weakest area across all images.
Format:
S01: composition NN, light NN, color NN, materials NN, detail NN
S01 gaps: 1) ... 2) ... 3) ...
Weakest: ...

Critic A (same model) and critic B (a different model) answer for S01:

A  S01: composition 72, light 60, color 50, materials 57, detail 50
B  S01: composition 68, light 56, color 54, materials 53, detail 48
   S01 gaps: 1) whole frame: walls and sea are grey, the reference is warm orange and teal
             2) far hills: one flat color, no trees or terraces  3) roofs: all the same red

No dimension differs by more than 10, so 2 critics are enough. The median of 2 values is their mean: composition 70, light 58, color 52, materials 55, detail 49. The builder's own estimate was 78. It is logged and does not count.

8.8 Send the stills, and do not wait

After every round the agent sends the stills with a short note: what changed, scores, next focus. It does not pause and does not end its turn to wait for a reply. Skill Leon: "It works in rounds and sends me screenshots after each round, without pausing. I give feedback whenever I get the chance to look at Claude's work, and it keeps going." Article

8.9 Run the stop check

It fails (section 6 explains the check). So round 2 starts at once.

Why the round has this shape
  • Focus on the weakest part: it moves the lowest score, and your feedback always comes first.
  • Side-by-side images: Leon's Greek world "looks pretty impressive, but the moment you put it next to the references it suddenly doesn't look THAT good anymore." Article The comparison shows the gap that a single image hides.
  • Measured numbers: a command cannot be too generous. A critic can.
  • Fresh critics: the builder made every choice, so it cannot judge them fairly. Video
  • The ledger: "Never claim a check that was not run. If something was not measured, write 'not measured'." Skill

Round 2 (23:05 to 00:10): fix the pipeline, and a critic spread

Example

Focus: color, because it has the largest total gap. The skill says: if everything is grey, check the pipeline before you repaint materials. The agent finds two causes: the output color space was linear, not sRGB, and the fog color was neutral grey. It sets sRGB output, ACES tone mapping with a new exposure, and a warm fog color taken from R02.

Measured: S01 saturation delta goes from −0.118 to −0.031.

Critic spread: critic A gives color 88, critic B gives color 74. They differ by 14, which is more than 10. So the agent adds critic C, which gives 84. The median of 74, 84 and 88 is 84.

Scores (S01 medians): composition 90, light 86, color 84, materials 82, detail 78. Mean 84.

23:40: your feedback, and the calibration offset

Leon's rule for feedback: give the agent a target. "Make it better" does not work. A target is a color, a timecode, a marked screenshot, or a distance. Article The skill logs your exact words in the inbox, handles them before critic items, and closes an item only with a still or clip that proves the fix. Skill

Example

You look at the round 2 stills before you go to sleep:

You, 23:40
Honestly this is 60 to 65%, not 84. The water at the quay in S03 looks like plastic. The far hills in S02 look empty in the half-wide shot. Going to sleep.

The agent does three things in the ledger:

  1. It logs 2 inbox items with your exact words: S03 water, S02 far hills.
  2. It sets the calibration offset. Your estimate is 62.5 (the middle of 60 to 65). The reported mean was 84. Offset = 62.5 − 84 = −21.5, logged as −21.
  3. It recalculates: round 2 calibrated is composition 69, light 65, color 63, materials 61, detail 57.

It does not reply with questions. You are asleep.

Why

The critics gave 84. You gave 62.5. "The user's estimate is the truth." Skill Without the offset, the agent would think it is at 84 and would aim too low. With it, every later score shows how far the work really is from your bar.

6. Phase C: the gate and the stop check (steps 9 and 10)

Step 9. The gate: no final render before you approve

Leon adds: "Render the matching shots as stills and show them to me first. Don't render the video before I approve." Article The skill: "Never start the final render, or any other long and costly export, before the user approves the stills in chat. While you wait, keep refining and test the render pipeline on a few short frames." Skill

Why

Rendering costs hours. The final 4K render of the Greek world took about 13 h of GPU time on Leon's integrated GPU. Article If the stills are wrong, all those hours are lost. A still costs seconds or minutes.

Example
You, 10:05
Stills approved. Render it.

Step 10. The stop check

The agent stops only when all three are true: Skill

  1. Every dimension in every shot meets the bar, by critic median after calibration.
  2. The time floor is reached (capped jobs have no floor).
  3. You approved the stills, and the final deliverable is rendered and its file is checked.

If the bar looks met before the floor, the skill says the bar "was read too low": the agent rereads the references at full size, checks far distance, color and the weakest shot, and starts another round. If a hard cap or a usage stop comes first, it finishes the round, logs it, and reports plainly what is still below the bar. Skill

Example

The stop check after round 10, before and after the render:

7. Phase D: ship (step 11)

What the skill does before the final render: Skill

  1. Test the pipeline at final settings on 3 to 5 seconds: correct frames, correct timing, audio in sync, the file plays.
  2. Measure seconds per frame and estimate the full render. Put the estimate in the progress note.
  3. Write frames to disk and skip existing frames on restart, so a crash or a usage stop does not cost the whole render.
  4. Encode at the end and add the audio.
  5. Check the final file with ffprobe: resolution, fps, duration, an audio stream. Export the first frame and look at it. Make a contact sheet.
Example

The 4-second test renders 120 frames at 6.8 s per frame (1080p, 16 sub-frames). The full video is 60 s × 30 fps = 1,800 frames. 1,800 × 6.8 s = 12,240 s, about 3.4 h. The agent reports: "Final render estimate 3.4 h, start 10:25, end about 13:50."

ffmpeg -framerate 30 -i frames/%05d.png -i music.wav -c:v libx264 -pix_fmt yuv420p -crf 16 \
  -c:a aac -b:a 320k -shortest -movflags +faststart final.mp4

ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,r_frame_rate:format=duration \
  -of compact final.mp4

ffmpeg -i final.mp4 -frames:v 1 cook/first_frame.png

music.wav is the track you added, because the brief said "download no".

The video rules for X

  • The first frame is the thumbnail and must be impressive alone. The first 1.5 seconds are the cover image. Skill
  • The best scene comes first. Then reveal more step by step, for example from behind a rock, then the camera rises. Skill
  • A new place every 6 to 7 seconds. Slow, cinematic camera moves. No text on screen. Skill
  • Licensed, free music, credited. 30 to 60 seconds. 1080p 30 fps is enough for X. Skill
Why

On X, the first frame decides if people watch, so it gets the best scene. The test render and the frames on disk protect hours of GPU time from one error. The ffprobe check follows the rule "Measure, do not assume". Skill

A public repo, only if the brief allows it

If the brief allows a push, the agent prepares a README, a docs/PROMPT.md with your real prompt (merged and cleaned up, not rewritten), credits, and honest numbers. Estimates are marked as estimates. It publishes only references that you made or own. Before anything goes public, it scans for keys and private data, for example with git grep -nIE "(sk-[A-Za-z0-9]|api[_-]?key|secret|token|BEGIN [A-Z ]*PRIVATE KEY)". The prompt file has the highest risk, because real prompts sometimes contain a pasted key. Posting is your action, not the agent's. Skill

Example

The brief says "push no". So the agent prepares the repo locally and tells you that it is ready. It does not push.

9. Resume after a context reset

All run state lives in cook/. These files are the agent's memory across context resets and the handoff to any other agent. Skill

  • If cook/BRIEF.md exists and the run is not shipped, the agent is resuming. It reads BRIEF, SHOTS and the last two ROUNDS entries, then starts the next round. It does not ask again, restart, or rebuild what works.
  • After every context compaction it does the same before its next action.
  • If cook/ holds a shipped run, it moves it to cook-archive/<date>/ and starts again at intake.
  • When you write "continue", it runs the next round. It does not answer with a recap.
Example

At 02:40 the context compacts. The agent reads BRIEF.md (bar, rules, floor, start 21:15), SHOTS.md, and the round 3 and 4 entries (offset −21, best so far round 4, next focus house detail). At 02:45 it starts round 5. You see no gap in the work.

Why

A 10 to 40 hour run will lose its context more than one time. "Write entries a stranger could act on." Skill Then you after a compaction, a cloud agent, or another model can continue from the files alone.

11. What the AI Labs video adds or changes

  • More reference tools. Dribbble (screenshot a section and paste it into the agent). The Inspo MCP, with a library of more than 800 websites. An Awwwards MCP. Vercel's agent-browser, which opens a site, scrolls, takes full-page screenshots, and can record video so the agent sees how animations move. Leon himself names only Mobbin, X and GPT Image. Video
  • Mockups as the target. For a page, the video says the target is a mockup: ask the agent for 3 different designs on one page, check them on small screens, and pick one. Mockups are cheap to change, so you try many designs with few tokens. Leon's article and the skill do not have this step. Video
  • A test of the number. AI Labs asked for 99% similarity to a complex site and judged the result at about 66%. The 3D figure whose head follows the mouse was "not close at all". Video
  • "Build step by step". The video says: build with no animations first, check the layout, then add the animations. Leon's article step 7 is about the render order (stills first, video later). The intent is the same (fix the cheap part before the expensive part), but the words differ. Video Article
  • A limit of ban lists. A ban only stops the patterns you name. The model then moves to its next default look, so you must add each new pattern. AI Labs' slop-detector skill keeps all patterns in one file. It does not flag one pattern alone, because one color fade can be a design choice. It flags a group of patterns on the same page. Video
  • Cook in practice. AI Labs installed the skill for one project with npx skills add Leonxlnx/cook. The skill asked about references, the bar, time and usage limits. The video warns: give it a time limit, because a design build "won't stop before 8 hours by default". Video (In the skill, the 8 h floor is the default for a demo or visual build. A small job gets a 1.5 h cap. Skill)

12. Gaps and limits I found in the sources

  1. The bar condition and a 99.9 target. The stop check needs every dimension at the bar. With a 99.9 bar that Leon calls "probably not" reachable, that condition will usually stay false. The skill does not say what ends the run when you approve the stills but the bar is not met. In the example, your approval and the checked file end the run, and the agent states the gap: calibrated 74 against 99.9. The skill does tell the agent to report "plainly what is still below the bar" when a cap or usage stop comes first.
  2. All similarity scores are eyeballed. Only the color check, frame times and the final file check are measured. The skill says so itself.
  3. The calibration offset is one number. The skill subtracts one offset from all dimensions. Your estimate can differ by dimension (for example, color worse than composition). The skill does not split it.
  4. Model names differ. The article says "GPT 6.1 Sol", "GPT Astra 6.1" and "GPT 6 Astra". The video says "GPT 6.1 Soul".
  5. Cost. Leon's Greek world cost about $1.8k to $2.3k at API prices and ran on a Max plan. A run of this size on API billing costs real money. The usage pacing protects a subscription window, not a budget.
